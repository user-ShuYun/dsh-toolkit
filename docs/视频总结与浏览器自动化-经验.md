# B 站视频总结 & 浏览器自动化 · 经验

> 2026-10 这一个月在这台机器上磨出来的。配套：`tools/fetch-bili.mjs`、`tools/split-chunks.mjs`、`tools/notes.mjs`、`out/write-note-general.mjs`。

---

## 一、总结一条 B 站视频的标准流程

```
1. 取字幕      node out/fetch-bili.mjs BV号        → out/<BV>.transcript.txt + .meta.json
2. 决定策略    <1.2 万字：一遍过；否则分块
3. 分块        node out/split-chunks.mjs <txt> <dir> 4~6
4. 逐块摘要    workflow 并发（每块 14k 字以内）
5. 合并        按「一句话结论 / 主线 / 数字 / 金句 / 适合谁看」骨架写
6. 存档        node out/write-note-general.mjs <BV> <summary.md>
```

**内置的 `/api/videoSummary` 只切前 1.2 万字**——4 小时的访谈会把 82% 的内容丢掉。所以长视频必须自己分块。

---

## 二、分块的粒度

| 视频长度 | 字幕字数 | 块数 | 单块 |
|---|---|---|---|
| 10 分钟 | 3 千 | 1 | 直接总结 |
| 20 分钟 | 8 千 | 1~2 | — |
| 90 分钟 | 2.8 万 | 4 | 7 千字 |
| 4.4 小时 | 8.2 万 | 6 | 1.4 万字 |

单块 1.4 万字是实测上限——再大摘要会开始丢细节。

---

## 三、写作骨架（读者最好用的那版）

```
一句话结论（≤60 字）
三条主线（每节 4~6 条 bullet，按重要性不按时间）
具体的方法与数字（只放钱/比例/时间/专名）
值得记的几句（金句 + 括号注明语境）
适合谁看（2 条：能拿走什么 + 一句提醒）
```

「按重要性不按时间」这一条最关键——按时间写出来就是流水账。

## 四、存档规范

- 路径：`notes/<UP主>/<YYYY-MM-DD>-<标题>.md`
- 必须含 front matter（title/up/bvid/url/duration/view/source/saved）
- 正文：总结 + 可折叠原始字幕（`<details>` 包 ```text）
- 用 `saveNote()`（`tools/notes.mjs` 导出）写入，它会自动重建 `notes/INDEX.md`
- **同一视频重复总结时**：`saveNote` 按日期命名，会生成第二份 → 传 `date` 参数覆盖旧文件，别产生重复条目

## 五、ChatGPT 网页自动化的坑（血泪）

### 5.1 Cloudflare 浏览器检查

| 现象 | 说明 | 处理 |
|---|---|---|
| 页面显示「无法加载你的账户 / 浏览器检查未能完成」 | 整个会话不可用，不是登录掉了 | **程序点「重新加载」无效**，必须真人点一次；通过后 cookie 恢复，无需重登 |
| 发消息报 `cloudflare_challenge` + 重试按钮 | 那次请求被拦 | `Page.reload` 刷新一次通常就好；别连续硬刷 |
| 新开标签页必触发检查 | 每次新 tab 都要过一次 | 宁可在**同一个标签页**里点「新聊天」，也不要开新 tab |

### 5.2 多会话抢占同一个标签页

两个 DSH 会话共用 9222 的 ChatGPT 标签页时会发生：

- 你的提示词被塞进别人的输入框（**未发送**，躺在 composer 里）
- 等待回答时抓到的是上一轮的内容
- 页面 busy 状态互相干扰，一直等不到图

**判断方法**：读 `document.body.innerText`，看最近一条用户消息是不是自己的。
**处理**：先读 composer 内容确认归属，是自己的草稿才清（用 `execCommand('selectAll')+delete`），不是就别碰。

### 5.3 提取回答时的「污染」

旧版提取逻辑是「取最后一个 `ChatGPT 说：` 之后的内容」。当回答还没开始渲染时，最后一条 `ChatGPT 说：` 属于**上一轮**，于是抓到「上一轮回答 + 本轮提问」的混合体。

**正确做法**：记录发送前的 body 文本长度作为基线，只在**基线之后**的新增文本里找标记；且要求「停止按钮消失 + 文本连续两次不变」才收。

### 5.4 图片生成

- 出图前必须 `gpt_status` 确认 `busy=false`
- 单通道：一次只发一条，生成中发第二条会被拒
- 「年轻女性 + 多视角全身设定稿」会被内容审核拒稿（改年龄到 20 岁也没用）→ 三视图交给本地模型

## 六、零碎但省命的命令

```powershell
node tools/bili.mjs state              # B 站登录态
node tools/bili.mjs search "关键词" 8   # 搜视频
node tools/bili.mjs subs BV号           # 只要字幕
node tools/notes.mjs search 关键词       # 全库检索
node tools/notes.mjs index              # 重建索引
```

## 七、判断「这条视频值不值得总结」

- 字幕 < 500 字：多半没字幕，直接看简介
- 标题带「一口气 / 保姆级 / 全流程」且时长 > 60 分钟：信息密度通常高，值得分块细读
- 纯 Vlog / 无口播：ASR 字幕会很碎，总结质量差，不如看评论
